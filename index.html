Computer Concepts: Software vs Hardware & Classification

🎯 EXAM IMPORTANT 2 MARKS 3 MARKS
📖 Exact Definitions

Program: A collection of instructions/code designed to perform a specific task.

Software: An organized collection of computer programs, procedures, and documentation that tells the computer what to do.

Hardware: The physical electronic and mechanical devices that make up the computer system (e.g., Processor/CPU, RAM, Hard Disk, Motherboard, I/O devices).

💡 Easy Student Explanation

Think of Hardware as the body and physical organs of a human being, while Software is the mind and thoughts that tell the body how to move, breathe, and act. You cannot touch software, but without it, the hardware is completely lifeless!

⚙️ Three Types of Software (Classification)
  1. 1. System Software: Software used to control, manage, and perform all system-level tasks of the computer hardware. It acts as the backbone of computing.
    Examples: Operating System (Windows, Linux), Compilers, Interpreters, Linkers, Loaders.
  2. 2. Utility Software: Software that provides support, maintenance, and additional convenient capabilities to the computer system and user.
    Examples: Calculator, Notepad, MS-Paint, Web Browsers, Media Player, Disk Defragmenter, Antivirus.
  3. 3. Application Software: Programs developed by or for users using high-level languages and databases for specific customized end-user tasks.
    Examples: Library Management System, Banking Software, Railway/Flight Ticket Reservation System, MS Office.

Topic 1.2

What is an Operating System? Dual Views & Core Goals

🎯 EXAM IMPORTANT 2 MARKS 5 MARKS
📖 Exact Textbook Definition

An Operating System (OS) is a collection of system software that manages computer hardware resources and provides common services for computer programs. It acts as an intermediary / interface between a user of a computer and the computer hardware.

💡 Easy Analogy: The Government or Master Conductor

Imagine the computer hardware (CPU, RAM, Disks, Printer) as raw government machinery and public resources. The Operating System is the Government: it does not produce any goods directly, but it allocates resources fairly, prevents chaos, enforces security, and makes it easy for citizens (users and applications) to get their work done!

Figure 1.1: Operating System as the Bridge between Users/Programs and Hardware
🎯 Primary Goals of an Operating System
  • 1. Convenience / Simplicity: Simplify program execution and problem-solving for users (User View).
  • 2. Efficiency: Maximize computer hardware utilization like CPU time and memory space (System View).
  • 3. Resource Sharing: Facilitate controlled, conflict-free sharing of hardware and software resources.
  • 4. Portability & Flexibility: Allow programs to run across varying underlying hardware without total rewriting.
  • 5. Isolation & Security: Ensure user programs cannot interfere with each other or with the OS kernel.
  • 6. System Reliability: Provide error confinement, fault tolerance, and graceful system recovery.
💡
Two Distinct Views of the OS (VIVA Favorite)

1. User View: Focuses on ease of use, convenience, responsiveness, and clean UI.
2. System View: Focuses on resource allocation, CPU scheduling, memory utilization, and preventing deadlocks.

Generations & History of Operating Systems

🎯 EXAM IMPORTANT 5 MARKS

The evolution of operating systems is directly tied to advancements in computer hardware architecture across 4 distinct generations:

1st Generation
(1945 – 1955)		 Vacuum Tubes & Mechanical Relays, Plugboards No Operating System. Programming strictly in pure machine code (binary 0s and 1s). Numerical calculations only. Enormous physical size, slow, high heat generation. Introduction of punch cards in the 1950s.

4th Generation
(1980 – Present)		 VLSI & Microprocessors (PCs, Workstations) Graphical User Interfaces (GUI), Network OS, Distributed OS, Personal Computers (Windows, macOS, Linux, Mobile OS: Android, iOS). Ubiquitous high-speed networking, handheld mobile devices, multicore processing, cloud environments.

Topic 1.4

Types of Operating Systems (Classification & Comparisons)

🎯 EXAM FAVORITE 5 MARKS

1. Simple Batch System vs. Multiprogramming Batch System

Simple Batch System: User submits jobs on punch cards/tapes to a human computer operator. The operator groups similar jobs into batches and feeds them into the computer. Jobs execute one after another with zero direct interaction between user and machine.

Multiprogramming Batch System: Several jobs are kept in main memory simultaneously. When the currently running job needs to wait for an I/O operation to complete, the CPU switches immediately to execute another ready job in memory. Thus, the CPU is never kept idle!

Figure 1.2: CPU Switching in Multiprogramming Systems

2. Multitasking / Time-Sharing Systems (TSS)

Time-Sharing extends multiprogramming to allow multiple interactive users to share the same computer simultaneously. Each process is allocated a fixed small quantum of CPU time (time slice) in Round-Robin fashion. Because context switches happen within milliseconds, every user gets the illusion that the entire system is dedicated exclusively to them!

⚡
Key Difference: Multiprogramming vs Time-Sharing

In Multiprogramming, the CPU switches only when a job needs I/O (objective: maximize CPU utilization). In Time-Sharing, the CPU switches when a fixed time slice expires, even if the job is ready to continue (objective: minimize response time for interactive users).

3. Multiprocessor (Parallel) Systems vs. Distributed Systems

Feature Multiprocessor System (Tightly Coupled) Distributed System (Loosely Coupled)
Architecture Multiple CPUs share a single common physical memory, system bus, power supply, and peripherals. Multiple independent physical computers, each with its own local private memory and CPU.
Coupling Tightly Coupled system. Loosely Coupled system.
Communication Ultra-fast communication via shared memory addresses. Communication via network cables/buses using message passing protocols.
Key Advantages Increased throughput, cost-saving (shared hardware), enhanced reliability (graceful degradation). Resource sharing across geographical distances, high fault tolerance, incremental scalability.

4. Real-Time Operating Systems (RTOS): Hard vs. Soft RTOS

An RTOS guarantees that critical system operations (such as interrupt handling and OS calls) will be completed strictly within a specified, rigid time constraint (deadline).

Characteristic Hard Real-Time System Soft Real-Time System
Deadline Strictness Guarantees that critical tasks are completed on time without exception. Critical tasks get highest priority, but completion within absolute deadline is not guaranteed.
Consequence of Missed Deadline Total system FAILURE and Catastrophe. Results become worthless. Degraded quality of service, but system does not fail catastrophically.
Real-World Examples Nuclear reactor control, Missile defence systems, Pacemakers, Aircraft flight controllers. Live audio/video streaming, Online gaming, Digital multimedia players.
Topic 1.5

Operating System Services (Functional & System Capabilities)

🎯 EXAM IMPORTANT 5 MARKS

The Operating System provides an environment for program execution and delivers essential services to programs and users:

📋 Core Services for User Programs
  1. 1. User Interface (UI): Command-Line Interface (CLI / Shell), Graphical User Interface (GUI), or Batch Interface.
  2. 2. Program Execution: Loading programs into memory, allocating CPU, running instructions, and terminating normally or abnormally with error logs.
  3. 3. I/O Operations: User programs cannot access raw hardware directly; the OS mediates all reading/writing through device drivers and buffers.
  4. 4. File-System Manipulation: Creating, reading, writing, searching, deleting files and directories, and enforcing file ownership permissions.
  5. 5. Inter-Process Communication (IPC): Exchanging data between processes on the same machine or over a network via shared memory or message passing.
  6. 6. Error Detection: Constantly detecting hardware errors (memory parity, power failure), I/O errors (paper out, bad sector), and user program errors (divide by zero, overflow) to take corrective recovery action.
🛡️ System Integrity & Resource Services
  1. 7. Resource Allocation: Fairly and efficiently allotting CPU cycles, main memory blocks, and I/O devices among concurrent users and jobs.
  2. 8. Accounting: Logging usage statistics and tracking which users consume how much CPU time, storage, and network bandwidth.
  3. 9. Protection & Security: Regulating access to resources, user authentication via passwords, and defending against invalid unauthorized network intrusions.

Topic 1.7

Operating System Structures: Layered, Monolithic & Microkernel

🎯 EXAM FAVORITE 5 MARKS

1. The Layered Approach

The operating system is broken into a number of discrete layers (Layer 0 to Layer N). Layer 0 is the Hardware, and Layer N is the User Interface. Each layer is constructed strictly on top of lower layers and only invokes functions/services of the layer directly beneath it.

⚖️
Pros & Cons of Layered Structure

Advantage: Simplicity of construction, modularity, and easy debugging (if error found in Layer 2, Layer 0 & 1 are guaranteed correct).
Disadvantage: Difficult to define layer boundaries cleanly; poor execution efficiency due to multiple layers of overhead.

2. Monolithic vs. Microkernel Architecture

Architectural Feature Monolithic Kernel (e.g., Traditional UNIX, Linux) Microkernel Approach (e.g., Mach, QNX, Minix)
Kernel Size & Design One large, complex single program running in kernel space. Removes non-essential components from kernel, keeping it minimal.
Where Components Run? File systems, device drivers, memory management all run in Kernel Mode. File systems, device drivers run as user-level server programs in User Mode.
Communication Simple, ultra-fast direct internal C function calls. Components communicate strictly via Message Passing through the microkernel.
Extensibility & Reliability Hard to modify (bug in a device driver crashes whole OS). Highly extensible and secure (crashed driver only restarts user process; kernel safe!).
Performance Superior raw performance (no message passing overhead). Lower performance due to heavy message passing & context switch overhead.

Virtual Machines (VM Concepts & Architecture)

🎯 EXAM IMPORTANT 3 MARKS
📖 Definition of Virtual Machine

A Virtual Machine (VM) abstracts the underlying physical hardware of a single computer (CPU, Memory, Storage, NIC) into several distinct, isolated execution environments, creating the illusion that each environment is running its own dedicated PC.

🔑 Key VM Terminology
  • Host Machine: The actual underlying physical hardware computer and host operating system.
  • Guest Machine: The virtualized operating system environment running inside the host.
  • Hypervisor / VMM (Virtual Machine Monitor): The software layer that manages, partitions, and allocates physical resources to multiple guest VMs concurrently.

Process Concept, Program vs. Process & Memory Layout

🎯 EXAM IMPORTANT 2 MARKS 5 MARKS
📖 Definition of Process

A Process is defined as a program in execution. It is not just the passive program code; it represents an active entity with a locus of control and runtime state.
FORMULA: Process = Program + Runtime Activities

Feature Program (Passive) Process (Active)
Nature Passive entity stored on disk (e.g., .exe file in secondary memory). Active entity loaded in RAM, currently competing for CPU execution.
Lifespan Permanent until explicitly deleted from storage. Temporary; created, executed, and terminated.
Resources Requires only disk space. Requires CPU time, RAM memory, registers, stack, and I/O devices.
Figure 2.1: Memory Layout of a Process in Main Memory (Stack, Heap, Data, Text)
⚡ Process Creation & Termination Events (Source Points)
When is a New Process Created?
  • System Initialization: OS boots and creates background daemon processes.
  • Process Creation Syscall: Running process calls fork() to spawn child.
  • User Request: User clicks an icon or enters command in CLI.
  • Batch Job Initiation: OS picks the next job from spool/queue.
When Does a Process Terminate?
  • Normal Exit (Voluntary): Task completes successfully (exit(0)).
  • Error Exit (Voluntary): Process discovers file missing and exits.
  • Fatal Error (Involuntary): Divide by zero, illegal memory segfault.
  • Killed by Other Process (Involuntary): Terminated via kill() syscall.
Topic 2.2

Process State Transitions (5-State Model & 7-State Suspended Model)

🎯 EXAM FAVORITE 5 MARKS
📖 5 Fundamental Process States
  1. NEW: The process is being created and loaded into memory.
  2. READY: The process is loaded in main memory and waiting to be assigned to the CPU by the scheduler.
  3. RUNNING: Instructions are currently being executed by the CPU.
  4. WAITING / BLOCKED: The process cannot execute until an event (I/O completion or signal) occurs.
  5. TERMINATED: The process has finished execution and its resources are released.
Figure 2.2: 5-State Process Transition Model
🔄 The 7-State Extended Model (Process Suspension & Swapping)

When physical RAM is completely full and no processes in memory are in the Ready state, the OS swaps blocked processes out to secondary storage (disk swap space) to free memory. This introduces 2 new suspended states:

  • 1. Blocked Suspend: The process is stored in secondary memory (disk) and is awaiting an event/I/O.
  • 2. Ready Suspend: The event has completed; the process is on disk and ready to execute the moment it is swapped back into main memory!
Topic 2.3

Process Control Block (PCB / Task Control Block)

🎯 EXAM FAVORITE 2 MARKS 5 MARKS
📖 Definition of PCB

A Process Control Block (PCB) is a critical data structure maintained by the Operating System for every active process. Identified by a unique integer Process ID (PID), it stores all tracking metadata required to manage and context-switch the process.

PCB Attribute Description & Purpose
Process ID (PID) Unique numerical identifier assigned to the process by the OS.
Process State Current execution status (New, Ready, Running, Waiting, Suspended).
Program Counter (PC) Points to the memory address of the next machine instruction to execute.
CPU Registers Saves hardware registers (accumulators, index registers, stack pointers) when interrupted.
CPU Scheduling Information Process priority, pointers to scheduling queues, and other scheduling parameters.
Memory Management Info Base and limit registers, page tables, or segment tables based on memory architecture.
Accounting Information CPU time used, real time elapsed, account numbers, time limits.
I/O Status Information List of I/O devices allocated to the process, list of open files.
Topic 2.4

Context Switching (Mechanism, Overhead & Thread Motivation)

🎯 EXAM IMPORTANT 2 MARKS 3 MARKS
📖 Definition of Context Switch

A Context Switch is the low-level procedure followed by the CPU to switch from executing one process to another. It requires saving the state (context) of the current process into its PCB and restoring the saved state of the new process from its PCB so that execution can resume seamlessly from where it left off.

⚠️
Crucial Exam Point: Context Switch Time is Pure Overhead!

During a context switch, the computer hardware is busy saving registers, flushing caches, and updating memory maps. The system performs zero useful user work during this duration! Typical switch times range from a few microseconds (< 10 μs), but in heavily loaded systems, this becomes a severe performance bottleneck—motivating the creation of Threads.

Topic 2.5

Threads, Multithreading Benefits & Thread Models

🎯 EXAM FAVORITE 5 MARKS
📖 Definition of Thread

A Thread is a basic unit of CPU utilization and a single sequence stream of execution within a process. Frequently called a Lightweight Process (LWP), a thread possesses its own Program Counter, Register set, and Stack, while sharing the code section, data section, and open files with other peer threads in the same process.

🌟 Five Core Benefits of Multithreading
  1. 1. Responsiveness: An interactive application remains responsive to user clicks even if one thread is blocked performing heavy I/O or computations.
  2. 2. Resource Sharing: Threads automatically share memory and file descriptors by default without expensive IPC setup.
  3. 3. Economy: Creating a thread and switching between threads is vastly cheaper and faster than allocating a full process PCB and address space.
  4. 4. Scalability: Threads can run completely in parallel across multiple physical CPU cores.
  5. 5. Smooth Context Switching: Minimizes context switch time and avoids cache invalidation penalties.

User-Level Threads (ULT) vs. Kernel-Level Threads (KLT)

Feature User-Level Threads (ULT) Kernel-Level Threads (KLT)
Management Managed completely by user-space thread library without kernel awareness. Supported, managed, and scheduled directly by the OS Kernel.
Switching Overhead Extremely fast; does not require kernel mode privileges or traps. Slower; requires mode switch into kernel space to change thread context.
Blocking Behavior Disadvantage: If one user thread makes a blocking system call, the entire process is blocked! Advantage: If one thread blocks, the kernel can immediately schedule another thread of the same process.
Multiprocessing Cannot take advantage of multiple CPU cores (kernel sees only 1 process). Can run parallel threads across multiple processors concurrently.

Multithreading Models

1. Many-to-One Model

Many user-level threads mapped to a single kernel thread. Thread management is efficient in user space, but one blocking call blocks all threads; cannot use multicore CPUs.

2. One-to-One Model

Maps each user thread to its own dedicated kernel thread. High concurrency; if one blocks, others run. (Used by Linux & Windows 95 to XP).

3. Many-to-Many Model

Multiplexes many user-level threads to a smaller or equal number of kernel threads. Combines the speed of ULT with true multicore execution of KLT.

Topic 2.6

Process Scheduling: Types of Schedulers & Queues

🎯 EXAM IMPORTANT 3 MARKS 5 MARKS
Scheduler Type Frequency of Execution Primary Role & Objective
Long-Term Scheduler
(Job Scheduler)		 Runs infrequently (seconds/minutes). Selects programs from the Job Pool (spool) and loads them into memory. Controls the Degree of Multiprogramming.
Short-Term Scheduler
(CPU Scheduler)		 Runs extremely frequently (milliseconds). Selects from among ready processes in RAM and allocates the CPU to one of them. Must be exceptionally fast!
Medium-Term Scheduler
(Swapper)		 Runs intermittently during memory pressure. Removes partially executed processes from RAM to disk backing store (swapping out) to reduce multiprogramming load, and swaps them back in later.
🗂️ Scheduling Queues
  • Job Queue: Set of all processes entering the computer system.
  • Ready Queue: Set of all processes residing in main memory, ready and waiting for CPU time.
  • Device Queues: Set of processes waiting for a specific I/O device (e.g., Disk queue, Printer queue).

CPU Scheduling Criteria & Performance Formulas

🎯 NUMERICAL FORMULAS 2 MARKS 5 MARKS
Criteria Definition & Objective Mathematical Formula
1. CPU Utilization Percentage of time the CPU is doing productive work (Target: Maximize, 40% light to 90% heavy). $$ ext{CPU Utilization} = rac{ ext{Busy Time}}{ ext{Total Time}} imes 100\%$$
2. Throughput Number of processes completed per unit of time (Target: Maximize). $$ ext{Throughput} = rac{ ext{Total Processes Completed}}{ ext{Total Time Elapsed}}$$
3. Turnaround Time (TAT) Total interval from submission to full completion (Target: Minimize). $$\mathbf{TAT = ext{Completion Time (CT)} - ext{Arrival Time (AT)}}$$

Topic 2.8

CPU Scheduling Algorithms (Solved Examples & Gantt Charts)

🎯 HIGH MARKS GUARANTEED 5 MARKS

1. First-Come, First-Served (FCFS) Scheduling

Non-preemptive algorithm managed by a simple FIFO queue. Process that arrives first gets the CPU first.

⚠️
The Convoy Effect in FCFS

A situation where multiple short CPU burst processes are forced to wait behind one massive, CPU-bound process holding the processor for a long duration. Causes low device utilization and dismal Average Waiting Time.

📊 Solved Numerical from PPT Slide 21 (Exam Ready)
SOLVED NUMERICAL

Problem: Four processes arrive at Time = 0 in order $P_1, P_2, P_3, P_4$ with Burst Times: $P_1 = 21 ext{ms}, P_2 = 3 ext{ms}, P_3 = 6 ext{ms}, P_4 = 2 ext{ms}$. Calculate Average Waiting Time (AWT).

Gantt Chart:

Waiting Times:

  • $WT(P_1) = 0 ext{ ms}$
  • $WT(P_2) = 21 ext{ ms}$
  • $WT(P_3) = 21 + 3 = 24 ext{ ms}$
  • $WT(P_4) = 24 + 6 = 30 ext{ ms}$

$$ ext{Average Waiting Time (AWT)} = rac{0 + 21 + 24 + 30}{4} = rac{75}{4} = \mathbf{18.75 ext{ ms}}$$

2. Shortest Job First (SJF) Scheduling

Selects the process with the shortest CPU burst time first. Proven to be provably optimal for minimizing average waiting time when all processes arrive at time 0.

  • Non-Preemptive SJF: Once CPU is given to a process, it cannot be interrupted until burst completes.
  • Preemptive SJF (SRTF — Shortest Remaining Time First): If a new process arrives with a remaining CPU burst shorter than the currently executing process, the current process is preempted!
  • Starvation Problem: Long jobs may wait indefinitely if shorter jobs keep arriving continuously.

3. Priority Scheduling & The Aging Solution

Each process is assigned a priority integer. The CPU is allocated to the highest-priority process. Equal priorities are resolved via FCFS.

💡
Problem: Indefinite Blocking (Starvation) & Solution: Aging

In a heavily loaded system, low-priority processes may starve forever. The solution is Aging: gradually increasing the priority of processes that wait in the system for long periods (e.g., increase priority by 1 every 15 minutes).

4. Round Robin (RR) Scheduling & Time Quantum $q$

Designed specifically for time-sharing systems. Each process gets a small unit of CPU time called a Time Quantum $q$ (typically 10 to 100 milliseconds). After time $q$ elapses, a hardware timer interrupts the CPU, the process is preempted and placed at the tail of the Ready Queue.

Value of Quantum $q$ System Behavior & Trade-off
$q$ is Very Large ($\infty$) Round Robin degenerates into simple FCFS policy.
$q$ is Very Small Excessive context switching overhead! CPU spends all time saving registers instead of doing real work. Rule of thumb: $q$ must be substantially larger than context switch time (< 10 μs).

5. Multilevel Queue (MLQ) vs. Multilevel Feedback Queue (MLFQ)

Algorithm Queue Structure & Movement Source Example Configuration
Multilevel Queue (MLQ) Partitions ready queue into separate queues (Foreground Interactive vs Background Batch). Processes cannot move between queues. Foreground queue uses Round Robin; Background queue uses FCFS. Fixed priority between queues.
Multilevel Feedback Queue (MLFQ) Allows processes to move dynamically between queues based on CPU burst behavior and aging. Queue $Q_0$: RR with $q = 8 ext{ms}$. If not finished, demoted to $Q_1$.
Queue $Q_1$: RR with $q = 16 ext{ms}$. If not finished, demoted to $Q_2$.
Queue $Q_2$: FCFS scheduling.

Topic 3.1

Inter-Process Communication (IPC) & Cooperating Processes

🎯 EXAM IMPORTANT 2 MARKS 3 MARKS
📖 Definition of IPC

Inter-Process Communication (IPC) refers to a mechanism and protocol that allows two or more concurrent processes to exchange data and synchronize their actions simultaneously.

Process Type Behavior & Characteristics
Independent Process Cannot affect or be affected by the execution of another process. Operates on private data only.
Cooperating Process Can affect or be affected by other executing processes. Shares data, code, or hardware resources.
🌟 Four Reasons Why Processes Cooperate (Why We Need IPC?)
  1. 1. Information Sharing: Multiple users or tasks need concurrent access to the same shared data (e.g., shared files, databases).
  2. 2. Computation Speedup: A complex problem can be partitioned into parallel subtasks running across multicore CPUs.
  3. 3. Modularity: Constructing system functions into separate cooperating modules/threads (clean software engineering).
  4. 4. Convenience: A user can run multiple tasks in parallel (e.g., printing, editing, and compiling at the same time).
Topic 3.2

Race Condition (Concept, Code Example & Risk)

🎯 HIGH PROBABILITY 2 MARKS 5 MARKS
📖 Exact Definition of Race Condition

A Race Condition is an undesirable situation that arises when two or more concurrent processes access and manipulate the same shared data simultaneously, and the final outcome of execution depends on the exact, unpredictable order in which instructions are interleaved.

💡 Classic Example: Shared Variable Counter Interleaving
EXAM EXAMPLE

Suppose shared variable count = 5. Process A executes count++ and Process B executes count-- concurrently:

At machine level:
Process A: R1 = count (5) → R1 = R1 + 1 (6) → count = R1 (6)
Process B: R2 = count (5) → R2 = R2 - 1 (4) → count = R2 (4)

If interrupted in the sequence:

  1. A loads count into R1 (5)
  2. A increments R1 to 6
  3. [Context switch to B!] B loads count (still 5) into R2
  4. B decrements R2 to 4
  5. B writes count = 4
  6. [Context switch back to A!] A writes count = 6

Result: count = 6 instead of the correct value 5! One update was completely lost because of race condition.

Topic 3.3

The Critical Section Problem & Three Essential Rules

🎯 EXAM FAVORITE 5 MARKS
📖 Definition of Critical Section

A Critical Section (CS) is a segment of code in which a process accesses and modifies shared resources (such as shared variables, common memory tables, or files). To prevent race conditions, only ONE process may execute inside its critical section at any given time.

Generic Structure of a Process with Critical Section C-Pseudocode
do { /* Entry Section: Requests permission to enter critical section */ entry_section(); /* Critical Section: Accesses and modifies shared data */ critical_section(); /* Exit Section: Notifies other waiting processes that CS is free */ exit_section(); /* Remainder Section: Non-critical operations */ remainder_section(); } while (true);
🏆 Three Mandatory Requirements for ANY Valid Critical Section Solution
  1. 1. Mutual Exclusion: If process $P_i$ is executing in its critical section, then no other process can be executing in its critical section. (Zero concurrency inside CS).
  2. 2. Progress: If no process is executing in its critical section and some processes wish to enter, then only those processes not executing in their remainder section can participate in deciding who enters next, and this selection cannot be postponed indefinitely.
  3. 3. Bounded Waiting: There must exist a bound or limit on the number of times other processes are allowed to enter their critical sections after a process has made a request to enter and before that request is granted (prevents starvation).
Topic 3.4

Solutions to CS: Hardware (Test-and-Set) & Software (Peterson's)

🎯 EXAM FAVORITE 5 MARKS

1. Flaw in Strict Alternation (Turn Variable)

Strict alternation uses a shared variable turn initialized to 0. Process 0 enters when turn == 0 and sets turn = 1 upon exit. Process 1 enters when turn == 1 and sets turn = 0 upon exit.

⚠️
Why Strict Alternation Fails:

It satisfies Mutual Exclusion, but FAILS PROGRESS! If Process 0 does not want to enter its CS, Process 1 cannot enter even if the CS is completely empty because turn == 0. One process is blocked by another process in its remainder section!

2. Hardware Approach: Test-and-Set (TSL) Instruction

Modern CPUs provide an atomic machine instruction TestAndSet that reads a memory word and sets it to true simultaneously in a single, non-interruptible hardware clock cycle.

Test-and-Set Definition & Mutual Exclusion Implementation C-Pseudocode
// Atomic Hardware Definition (Executed uninterrupted) boolean TestAndSet(boolean *target) { boolean rv = *target; *target = true; return rv; } // Mutex Implementation using Lock (shared boolean lock = false): do { while (TestAndSet(&lock)) ; // Busy wait until lock is false /* Critical Section */ lock = false; // Release lock /* Remainder Section */ } while (true);

3. Peterson's Algorithm (Provably Correct 2-Process Solution)

Peterson's algorithm is a classic software solution for 2 processes ($P_0$ and $P_1$). It combines flag[2] (indicating interest to enter) and turn (yielding priority politely to the other process).

Peterson's Algorithm for Process i (where j = 1 - i) C-Pseudocode
boolean flag[2] = {false, false}; int turn = 0; // Code for Process i: do { flag[i] = true; // I am interested in entering CS turn = j; // Politely give turn to the other process j // Wait if j wants to enter AND it is j's turn while (flag[j] && turn == j) ; /* Critical Section */ flag[i] = false; // Done with CS; clear interest /* Remainder Section */ } while (true);
🏆
Proof that Peterson's Algorithm Satisfies All 3 Conditions:

1. Mutual Exclusion: For both $P_i$ and $P_j$ to enter simultaneously, both turn == j and turn == i must be true at once, which is impossible since turn can hold only one integer!
2. Progress: If $P_j$ is not interested (flag[j] == false), $P_i$ breezes past the while loop instantly.
3. Bounded Waiting: $P_i$ waits at most one turn because when $P_j$ exits, it clears flag[j] or yields turn = i.

Topic 3.5

Semaphores (Definition, Atomic Operations & Types)

🎯 EXAM FAVORITE 2 MARKS 5 MARKS
📖 Definition of Semaphore

A Semaphore $S$ is an integer synchronization variable that, apart from initialization, is accessed only through two standard atomic operations: wait(S) (also known as $P$, down, or decrement) and signal(S) (also known as $V$, up, or increment).

Atomic Semaphore Primitive Definitions C-Pseudocode
// wait() or down() operation: decrements S; blocks if S <= 0 wait(Semaphore S) { while (S <= 0) ; // busy wait (or sleep in non-busy implementation) S--; } // signal() or up() operation: increments S; wakes up sleeping process signal(Semaphore S) { S++; }
Semaphore Type Domain Range Primary Use Case & Behavior
Counting Semaphore Unrestricted integer domain ($0$ to $+N$). Used to coordinate access to a finite pool of $N$ identical resources. Initialized to $N$. Each wait() claims a resource; each signal() frees a resource.
Binary Semaphore (Mutex) Restricted strictly to binary values: $0$ or $1$. Used to implement Mutual Exclusion for a single critical section. Initialized to $1$. First process sets it to $0$; subsequent processes wait until it is signalled back to $1$.
Topic 3.6

Monitors (High-Level Synchronization Construct)

🎯 EXAM IMPORTANT 3 MARKS
📖 Definition of Monitor

A Monitor is a high-level synchronization primitive that bundles shared variables, procedures, and data structures inside an enclosed module. The compiler guarantees that only one process can be active inside the monitor at any given time, thereby enforcing mutual exclusion automatically without error-prone manual semaphore pairing!

🔑 Condition Variables in Monitors

To allow processes to wait for certain conditions, monitors define Condition Variables (e.g., condition x, y;) with two operations:

  • x.wait(): The calling process is suspended until another process executes a signal on x.
  • x.signal(): Resumes exactly one suspended process waiting on x. If no process is waiting, the signal has no effect.
Topic 3.7

Classical Problem 1: Producer-Consumer (Bounded-Buffer)

🎯 TOP EXAM QUESTION 5 MARKS

A producer produces items into a shared buffer of fixed size $N$, and a consumer removes items from it. Constraints: Producer cannot produce if buffer is full; Consumer cannot consume if buffer is empty; buffer access must be mutually exclusive.

Semaphore Solution to Bounded Buffer (Slide 15) C-Pseudocode
#define N 100 // Buffer capacity typedef int semaphore; semaphore mutex = 1; // Controls critical section access to buffer semaphore empty = N; // Counts empty buffer slots (starts at N) semaphore full = 0; // Counts filled buffer slots (starts at 0) void producer(void) { int item; while (true) { item = produce_item(); wait(empty); // Decrement empty count; sleep if buffer is full wait(mutex); // Enter critical section insert_item(item); // Place item into buffer slot signal(mutex); // Exit critical section signal(full); // Increment full count; wake up consumer } } void consumer(void) { int item; while (true) { wait(full); // Decrement full count; sleep if buffer is empty wait(mutex); // Enter critical section item = remove_item(); // Remove item from buffer signal(mutex); // Exit critical section signal(empty); // Increment empty count; wake up producer consume_item(item); } }
Topic 3.8

Classical Problem 2: Readers-Writers Problem

🎯 TOP EXAM QUESTION 5 MARKS

A database is shared among concurrent readers and writers:

  • Reader + Reader ($R + R$): NO PROBLEM! Multiple readers can read simultaneously.
  • Writer + Writer ($W + W$) or Writer + Reader ($W + R$): PROBLEM! Writers must have exclusive database access.
Readers-Writers Semaphore Solution (Slide 18) C-Pseudocode
semaphore mutex = 1; // Protects readcount variable semaphore db = 1; // Controls database access for writers int readcount = 0; // Number of readers reading void reader(void) { wait(mutex); readcount++; if (readcount == 1) wait(db);// First reader locks database against writers signal(mutex); read_database(); // Reading happens concurrently wait(mutex); readcount--; if (readcount == 0) signal(db);// Last reader frees database for writers signal(mutex); } void writer(void) { wait(db); // Gain exclusive access write_database(); // Writing signal(db); // Release exclusive access }
Topic 3.9

Classical Problem 3: Dining Philosophers Problem

🎯 TOP EXAM QUESTION 5 MARKS

Five philosophers ($P_0, P_1, P_2, P_3, P_4$) sit around a circular table with 5 bowls of rice and 5 chopsticks ($C_0, C_1, C_2, C_3, C_4$). A philosopher alternates between Thinking and Eating. To eat, a philosopher requires TWO chopsticks (left and right).

⚠️
Deadlock Scenario (Circular Wait):

If all 5 philosophers get hungry at the exact same moment and pick up their left chopstick simultaneously, every chopstick semaphore becomes 0! When they try to pick up their right chopstick, everyone is blocked indefinitely. This is a classic DEADLOCK.

🛡️ Solution: The Asymmetry / Swapping Approach (Slide 63)

To eliminate the circular wait condition, create an asymmetric philosopher:

  • Philosophers $P_0, P_1, P_2, P_3$ pick up their left chopstick first, then right.
  • Philosopher $P_4$ (the last philosopher) swaps the order: picks up the right chopstick first, then left!
  • This asymmetry breaks the circular chain of dependencies and guarantees that deadlock can never occur!

Topic 4.1

What is a Deadlock? (Definition & Real-World Bridge Analogy)

🎯 EXAM IMPORTANT 2 MARKS 3 MARKS
📖 Exact Textbook Definition

In a multiprogramming system, several processes compete for a limited number of resources. A Deadlock is a situation where two or more processes are unable to proceed because each is waiting for an event (or resource) that can only be triggered (or released) by another waiting process in the set.

🚗 The Real-World Bridge Crossing Analogy (Slide 4)

Imagine traffic moving across a narrow, single-lane bridge from opposite directions:

  • Each section of the bridge is viewed as a non-sharable resource.
  • If cars from both ends meet in the middle, neither can move forward.
  • Deadlock can only be resolved if one or more cars back up (which corresponds to resource preemption and process rollback).
  • If cars continually arrive from one direction, cars from the other direction may suffer Starvation!
Topic 4.2

Resource System Model (Three-Step Lifecycle)

2 MARKS

Under normal operation, a process may utilize resources only in the following sequence:

  1. 1. Request: Process requests the resource. If not available immediately, process enters waiting state.
  2. 2. Use: Process operates on the resource (e.g., printing to printer, reading from disk).
  3. 3. Release: Process finishes its work and voluntarily releases the resource back to the OS pool.
Topic 4.3

Four Necessary & Sufficient Conditions for Deadlock

🎯 TOP EXAM QUESTION 5 MARKS

A deadlock can arise if and only if all four of the following conditions hold simultaneously in the system (known as Coffman Conditions):

Condition Exact Meaning Real Example
1. Mutual Exclusion At least one resource must be held in a non-sharable mode (only one process can use it at a time). Printer, CD-Recorder, Tape drive.
2. Hold and Wait A process must currently be holding at least one resource while simultaneously waiting to acquire additional resources held by other processes. Process holding Tape Drive and requesting Printer.
3. No Preemption Resources cannot be forcibly confiscated from a process; a resource can only be released voluntarily by the process holding it after task completion. OS cannot snatch a printer midway through a print job.
4. Circular Wait A closed circular chain of processes exists: $\{P_0, P_1, \dots, P_n\}$ such that $P_0$ waits for a resource held by $P_1$, $P_1$ waits for $P_2$, and $P_n$ waits for $P_0$. $P_1$ holds $R_1$, waits for $R_2$; $P_2$ holds $R_2$, waits for $R_1$.
Topic 4.4

Resource Allocation Graph (RAG) & Cycle Detection

🎯 DIAGRAM FAVORITE 5 MARKS
📖 Graph Properties of RAG
  • Process Nodes: Represented as circles: $\{P_1, P_2, \dots, P_n\}$.
  • Resource Nodes: Represented as rectangles/squares: $\{R_1, R_2, \dots, R_m\}$. Dots inside indicate the number of physical instances of that resource.
  • Request Edge ($P_i o R_j$): Directed arc from process to resource indicating $P_i$ has requested $R_j$ and is waiting.
  • Assignment Edge ($R_j o P_i$): Directed arc from resource instance dot to process indicating $R_j$ is allocated to $P_i$.
Figure 4.1: Cycle Theorems in Resource Allocation Graphs (Single vs Multiple Instances)
⚖️
RAG Cycle Theorems (Essential for Exams)

1. If the graph contains NO CYCLES $\implies$ System is GUARANTEED NOT IN DEADLOCK.
2. If the graph contains a CYCLE AND each resource category has ONLY 1 INSTANCE $\implies$ DEADLOCK EXISTS!
3. If the graph contains a CYCLE BUT resources have MULTIPLE INSTANCES $\implies$ Deadlock is possible, but NOT GUARANTEED.

Topic 4.5

Four Methods of Handling Deadlocks (Overview)

🎯 EXAM IMPORTANT 3 MARKS
Strategy Principle Practical Trade-off
1. Deadlock Prevention Design system protocols to strictly ensure at least one of the 4 Coffman conditions can never hold. Tends to result in poor device utilization and low system throughput.
2. Deadlock Avoidance System inspects resource requests dynamically to ensure it stays strictly within a Safe State. Requires advance knowledge of maximum resource demands for every process.
3. Detection & Recovery Allow deadlocks to occur, periodically run detection algorithms, and recover via termination or preemption. Overhead of periodic checking; aborted processes lose computed work.
4. Deadlock Ignorance (Ostrich Algorithm) Pretend deadlocks never happen! Used if deadlocks are rare and cheaper to ignore. Standard in Windows & Linux (manual user reboot if frozen).
Topic 4.6

Deadlock Prevention Techniques (Invalidating Coffman Conditions)

🎯 HIGH FREQUENCY QUESTION 5 MARKS
🛠️ How to Prevent Each of the 4 Conditions:
  1. 1. Invalidate Mutual Exclusion:
    Make resources sharable (e.g., read-only files can be shared by multiple processes simultaneously).
    Feasibility: Not feasible for inherently dedicated hardware like printers or tape drives.
  2. 2. Invalidate Hold & Wait:
    • Conservative Approach: A process must request and be allocated all its required resources before it starts executing. (Very low resource utilization).
    • Do Not Hold: A process can request resources only when it has none; before making a fresh request, it must release all currently held resources.
    • Wait Timeouts: Place a maximum timeout threshold; upon expiry, the process must release all its held resources.
  3. 3. Invalidate No Preemption:
    If a process holding some resources requests another resource that cannot be immediately allocated, then all resources currently held by this process are preempted (confiscated). The process is placed back in the waiting queue and restarts only when it regains old and new resources.
  4. 4. Invalidate Circular Wait (Most Practical & Common):
    Assign a strict natural number $f: R o \mathbb{N}$ to every resource type (e.g., Tape Drive = 1, Disk = 2, Printer = 3).
    Enforce the rule that processes can request resources only in strictly increasing (or decreasing) numerical order! If a process needs resource 1 and currently holds resource 3, it must first release resource 3. Circular wait is mathematically impossible!
Topic 4.7

Deadlock Avoidance, Safe State & Safe Sequence

🎯 EXAM FAVORITE 5 MARKS
📖 Definition of Safe State & Safe Sequence

A system state is Safe if the system can allocate resources to each process (up to its stated maximum requirement) in some order without entering a deadlock.

Formally, a state is safe if there exists a Safe Sequence of processes $\langle P_0, P_1, P_2, \dots, P_n angle$ such that for each process $P_i$, the resources that $P_i$ can still request can be satisfied by the currently available resources plus the resources held by all prior processes $P_j$ (where $j < i$).

💡
Crucial Exam Distinction: Safe vs. Unsafe vs. Deadlocked State

• All Safe states are deadlock-free.
• An Unsafe state is NOT necessarily a deadlock; it merely has the potential to degenerate into deadlock if processes request their maximum demands.
• Deadlock avoidance algorithms (such as the Banker's Algorithm) ensure the system never leaves the Safe state space!

Topic 4.8

Deadlock Recovery (Process Termination vs. Resource Preemption)

🎯 EXAM IMPORTANT 3 MARKS
Recovery Strategy Approaches & Mechanisms Considerations & Overheads
1. Process Termination • Abort all deadlocked processes: Breaks cycle immediately, but extremely costly (discards all intermediate computations).
• Abort one process at a time: Abort one victim, run detection algorithm again, repeat until deadlock cycle is broken. 		Select victim based on lowest priority, least CPU time consumed, or fewest resources held.
2. Resource Preemption • Selecting a Victim: Decide which process to preempt to minimize overall cost.
• Rollback: Roll victim process back to a previous safe checkpoint.
• Prevent Starvation: Ensure the same process is not repeatedly chosen as victim (include number of rollbacks in cost function). 		Requires checkpointing support in OS; starvation must be explicitly guarded against.

Topic 5.3

Address Binding Stages, Loading & Linking

🎯 EXAM IMPORTANT 3 MARKS
🕒 Three Stages of Address Binding
  1. 1. Compile Time: If it is known at compile time where the process will reside in memory, absolute code is generated (e.g., MS-DOS .com). If the starting location changes later, the code must be completely recompiled!
  2. 2. Load Time: If memory location is not known at compile time, the compiler generates relocatable code. Final binding is delayed until the loader places the code in memory.
  3. 3. Execution Time (Run Time): If the process can be moved from one memory segment to another during execution (e.g., swapping or virtual memory), binding is delayed until execution. Requires special hardware (MMU base/limit registers).
Operation Static Approach Dynamic Approach
Loading Static Loading: Entire program and all routines are loaded into RAM before startup. Faster execution, but very inefficient memory utilization. Dynamic Loading: A routine is loaded into memory only when it is actually called by the program. Unused routines (e.g., error handlers) never consume RAM.
Linking Static Linking: System libraries and language routines are combined by the linker into the binary executable image on disk at compile time. Dynamic Linking: Linking is postponed until execution. A small stub in code locates shared libraries (e.g., .dll in Windows, .so in Linux), saving immense disk and RAM space!

Swapping is a memory management scheme where a process can be temporarily swapped out of main memory to a secondary storage backing store (disk swap space), and later swapped in (brought back into memory) for continued execution. This allows the total physical memory requirements of active processes to exceed the actual physical capacity of RAM.

Topic 5.5

Contiguous Allocation: Fixed Partitioning (MFT) vs. Variable Partitioning (MVT)

🎯 EXAM FAVORITE 5 MARKS

In Contiguous Memory Allocation, each program must occupy a single continuous, adjoining block of memory addresses.

Feature Fixed Partitioning (MFT — Multiprogramming with Fixed Tasks) Variable Partitioning (MVT — Multiprogramming with Variable Tasks)
Partition Creation RAM is divided into a fixed number of static partitions at boot time. Partitions are created dynamically to match the exact memory requested by each arriving process.
Degree of Multiprogramming Fixed & Limited: Number of simultaneous processes cannot exceed the number of partitions. Dynamic: Varies depending on process sizes and available memory.
Type of Fragmentation Suffers severely from Internal Fragmentation. Completely eliminates internal fragmentation, but suffers from External Fragmentation.
Implementation Extremely simple; low OS overhead. More complex; OS must maintain dynamic linked lists of allocated blocks and free memory holes.
Topic 5.6

Internal vs. External Fragmentation & Compaction

🎯 VIVA & EXAM FAVORITE 2 MARKS 3 MARKS
Fragmentation Type Exact Definition Source Example
Internal Fragmentation Memory allocated to a process is slightly larger than the memory requested. The unusable unused space inside the allocated partition is wasted. In MFT, if partition size is $500 ext{ KB}$ and arriving process needs $400 ext{ KB}$, $100 ext{ KB}$ inside that partition is wasted!
External Fragmentation Total free memory space in the system is sufficient to satisfy a request, but the free storage is fragmented into tiny non-contiguous blocks, so an arriving process cannot fit. In MVT, three separate holes of $50 ext{ KB}$ exist ($150 ext{ KB}$ total free), but a new process needing $120 ext{ KB}$ cannot be loaded!
💡
Compaction (Solution for External Fragmentation):

Compaction moves all active processes towards one end of memory (e.g., top), consolidating all scattered free holes into one single large continuous block of free memory.
Major Drawback: Extremely costly in CPU overhead because running processes must be halted, memory relocated, and pointers updated. It is possible only if relocation is dynamic at execution time!

Topic 5.7

Dynamic Storage Allocation Strategies (First Fit, Best Fit, Worst Fit)

🎯 HIGH FREQUENCY 3 MARKS
Strategy Search Procedure Characteristics & Performance
First Fit Allocates the first hole that is big enough from the beginning of the free list. Fastest algorithm; low search time. Generally superior in overall speed and storage utilization.
Best Fit Searches the entire list and allocates the smallest hole that is big enough. Minimizes wasted leftover space in that partition, but produces many tiny, unusable leftover fragment holes.
Worst Fit Searches the entire list and allocates the largest available hole. Leaves behind the largest leftover hole, which might be large enough to host another process, but performs poorly in practice.
Topic 5.8

Paging (Architecture, Page Table & Address Translation)

🎯 TOP EXAM QUESTION 5 MARKS
📖 Fundamental Paging Principles

Paging is a non-contiguous memory management scheme that permits the physical address space of a process to be non-contiguous, thereby completely eliminating external fragmentation.

  • Frames: Physical memory (RAM) is divided into fixed-size blocks called Frames.
  • Pages: Logical memory (Process) is divided into blocks of the exact same size called Pages.
  • CRITICAL RULE: Page Size == Frame Size (Defined by hardware, power of 2)
⚙️ Address Translation Mechanism in Paging

Every address generated by the CPU is divided into two distinct components:

  • Page Number ($p$): Used as an index into the process's Page Table. The page table contains the corresponding base physical frame number ($f$) where page $p$ is stored in RAM.
  • Page Offset ($d$): Combined with the base frame address to define the exact byte within the physical frame. (Offset remains unchanged: $d_{ ext{logical}} = d_{ ext{physical}}$).
Figure 5.3: Paging Hardware Address Translation Architecture (Logical (p, d) to Physical (f, d))
🧮
Mathematical Example from PPT Slide 31:

If Physical Address ($PA$) has 19 bits, then Physical Address Space ($PAS$) = $2^{19} ext{ words} = \mathbf{512 ext{ K words}}$.
If Physical Address Space is $256 ext{ M words}$, then $PAS = 2^{28} ext{ words} \implies \mathbf{28 ext{ bits}}$ are required for Physical Address!

🛡️ Memory Protection in Paging

Memory protection is implemented by associating protection bits with each entry in the page table:

  • Valid / Invalid Bit: Set to Valid if the associated page is currently in the process's logical address space and resides in RAM; set to Invalid if the page is not in memory or illegal (generates page fault / trap).
  • Access Rights Bits: Read-Only, Read-Write, or Execute-Only permissions.
Topic 5.9

Segmentation (User View of Memory & Segment Table)

🎯 EXAM FAVORITE 5 MARKS
📖 Definition of Segmentation

Segmentation is a memory management scheme that supports the user/programmer's modular view of memory. A program is viewed not as a flat array of bytes, but as a collection of variable-length logical units called Segments (e.g., Main program, Subroutines, Stack, Symbol Table, Global Data).

⚙️ Address Translation in Segmentation

Logical address consists of a two-tuple: $\langle ext{Segment-Number } s, ext{ Offset } d angle$.

  1. Segment number $s$ indexes the Segment Table.
  2. Each entry has two registers: Limit (length of segment) and Base (starting physical address in RAM).
  3. Hardware check: Is offset $d < ext{Limit}$?
  4. If $d \ge ext{Limit}$, hardware traps to OS: Addressing Error (Segmentation Fault)!
  5. If legal, $ ext{Physical Address} = ext{Base} + d$.

Topic 6.2

Device Controllers (Electronic Hardware Interface)

🎯 EXAM IMPORTANT 2 MARKS 3 MARKS
📖 Definition of Device Controller

A Device Controller is an electronic collection of components (typically a specialized integrated chip or circuit board) that can operate a port, bus, or physical hardware device. It acts as the hardware bridge between the computer system bus and the electromechanical physical device.

🔌 Controller Components & Registers

The controller converts serial bit streams from the device into blocks of bytes for the CPU. It contains four internal hardware registers:

  • Data-In Register: Read by the CPU to receive input data from the device.
  • Data-Out Register: Written by the CPU to send output data to the device.
  • Status Register: Read by the CPU to check if device is busy, error flags, or ready.
  • Control Register: Written by the CPU to issue commands (e.g., start read, seek sector).
Topic 6.3

Memory-Mapped I/O vs. Isolated (Port-Mapped) I/O

🎯 HIGH FREQUENCY 3 MARKS 5 MARKS
📖 Definition of Memory-Mapped I/O

In Memory-Mapped I/O, the same unified address space is shared between main memory (RAM) and I/O device controllers. Certain address ranges represent RAM memory cells, while other designated address ranges map directly to the registers of device controllers.

Feature Memory-Mapped I/O Isolated / Port-Mapped I/O
Address Space Single unified address space shared by memory and I/O. Separate, dedicated I/O address space (I/O Ports).
Machine Instructions Standard CPU memory instructions (MOV, LOAD, STORE) access both memory and I/O registers! Requires special privileged CPU I/O instructions (e.g., IN, OUT).
Advantages Much simpler programming; device drivers can be written in pure C without assembly; standard address protection mechanisms work. Does not consume RAM address space; simpler hardware decoding.
Disadvantages Hardware caching of device registers must be disabled; requires dedicated bus snooping. Requires special instructions; cannot use standard pointer arithmetic on I/O.
Topic 6.4

Direct Memory Access (DMA) & Transfer Modes

🎯 TOP EXAM QUESTION 5 MARKS
📖 Definition of DMA

Direct Memory Access (DMA) is a specialized hardware mechanism that allows high-speed I/O devices (such as hard disks) to transfer an entire block of data directly to or from main memory (RAM) without continuous intervention from the CPU.

⚙️ Step-by-Step Working & Handshake Signals of DMA
  1. CPU Setup: CPU programs the DMA Controller registers with: I/O device address, starting RAM address, number of bytes to transfer, and transfer direction (Read/Write).
  2. Bus Request (HOLD): When data is ready, DMA asserts the HOLD signal on the CPU bus.
  3. Hold Acknowledge (HLDA): CPU completes its current bus cycle, suspends bus control, and asserts HLDA to grant the bus to the DMA controller.
  4. Direct Transfer: DMA places addresses on the memory bus and transfers data directly between device and RAM at hardware bus speeds!
  5. Interrupt on Completion: When byte count reaches zero, the DMA controller generates an Interrupt to notify the CPU that the transfer has finished.
DMA Transfer Mode Operation & Behavior
1. Burst Mode (Block Mode) Once DMA receives HLDA, it takes complete control of the system bus and transfers the entire bulk block of data in one uninterrupted burst. CPU is halted until the entire block finishes.
2. Cycle Stealing Mode The DMA controller takes control of the bus for only one bus cycle per word, transferring one data word and immediately releasing the bus back to the CPU. It "steals" cycles while the CPU is doing internal ALU work!
Topic 6.5

I/O Communication Methods: Polling vs. Interrupt-Driven I/O

🎯 EXAM FAVORITE 3 MARKS 5 MARKS
Feature Polling (Programmed I/O) Interrupt-Driven I/O
Mechanism CPU repeatedly reads the device status register in a tight loop (busy waiting) waiting for it to become ready. CPU issues an I/O command and continues doing useful work. When the device is ready, it signals the CPU via an Interrupt wire.
CPU Utilization Very poor; CPU is 100% wasted waiting for slow mechanical hardware. High; CPU does other useful computation while I/O operates concurrently.
Best Suited For Very fast devices or dedicated microcontrollers where waiting time is negligible. General-purpose computing and slow/irregular I/O (keyboards, disks, mice).
💡
Device Classification: Dedicated vs Shared Devices (Slide 19)

• Dedicated Devices: Can be allocated to only one user/process at a time (e.g., Printer, CD-ROM writer). Allocation of dedicated devices can lead to deadlocks if not managed carefully.
• Shared Devices: Can be concurrently accessed by multiple processes without conflict or deadlock (e.g., Magnetic Disks).

Topic 6.6

Goals & Principles of I/O Software

🎯 EXAM IMPORTANT 3 MARKS
  1. 1. Device Independence: Programs can access any I/O device without needing to know hardware-specific implementation details (e.g., reading from a hard disk, USB drive, or floppy disk uses the exact same read() system call).
  2. 2. Uniform Naming: The name of a file or device should simply be a string or integer and not depend on the device in any way (e.g., in UNIX, devices look like normal files in /dev/).
  3. 3. Error Handling: Errors should be handled as close to the hardware as possible. If the controller discovers a read error, it should try to correct it itself; only if unrecoverable should it escalate up to the driver and OS.
  4. 4. Buffering: Storing data in transit in memory to smooth out speed mismatches between producer and consumer.
Topic 6.7

Interrupt Mechanism, The Interrupt Cycle & ISR Execution

🎯 TOP EXAM QUESTION 5 MARKS
📖 Definition of Interrupt

An Interrupt is an asynchronous event and electrical signal sent over hardware wires (such as the INTR pin) to the CPU from a device controller that demands the immediate attention of the microprocessor.

🔄 Three Stages of the CPU Instruction Cycle with Interrupts

Under interrupt-driven I/O, the CPU hardware instruction cycle consists of three sub-cycles:

1. Fetch Cycle  →  2. Execution Cycle  →  3. Interrupt Cycle
  1. At the end of every instruction execution cycle, the CPU hardware checks if the Interrupt Request line (INTR) is asserted and the interrupt flag is enabled.
  2. If an interrupt is detected, the CPU initiates the Interrupt Cycle: it pushes the current Program Counter (PC) and processor status word flags onto the stack.
  3. CPU loads the Program Counter with the vector address of the Interrupt Handler (Interrupt Service Routine — ISR) from the Interrupt Vector Table.
  4. Control transfers to the ISR, which determines the cause of the interrupt and performs the required device data transfer.
  5. Upon completion, the ISR executes the IRET (Interrupt Return) instruction, which pops the saved Program Counter from the stack and seamlessly returns the CPU to the exact instruction prior to the interrupt!
Topic 6.8

Device Drivers (Architecture & Responsibilities)

🎯 EXAM IMPORTANT 2 MARKS 3 MARKS
📖 Definition of Device Driver

A Device Driver is an operating-system-specific and hardware-dependent software program that knows the detailed register layout and command set of a specific device controller. It acts as a translator between the generic, device-independent I/O software of the OS and the device controller hardware.

I/O Software Layer Responsibilities & Scope
Device-Independent I/O Software Common across all devices: uniform naming, device protection, buffer caching management, storage block allocation, and reporting errors to user applications.
Device Driver (Device-Specific) Specific to a particular hardware device: writes commands to controller registers, checks status bits, and handles device interrupts.
Topic 6.9

I/O Buffering Schemes (Single, Double & Circular Buffering)

🎯 HIGH FREQUENCY 3 MARKS 5 MARKS
📖 Why is Buffering Necessary?

A Buffer is a designated area of main memory that temporarily stores data while it is being transferred between two devices or between a device and an application.

  • Copes with speed mismatches: Bridges extremely fast CPU execution with slow mechanical disk/network arrivals.
  • Accommodates different data transfer sizes: Packets reassembled from streams before delivering to applications.
  • Supports application copy semantics: Ensures data does not change between write call and disk write.
Buffering Scheme Working Principle Performance & Trade-off
1. No Buffering Process communicates directly with the physical device without an intermediate OS buffer. Process must wait idle for all physical I/O to complete; very poor CPU utilization.
2. Single Buffering OS assigns a single memory buffer in kernel space for the I/O operation. Input device reads into buffer; once full, OS transfers it to user space. Process can read from user memory while input device fills kernel buffer, but sequential delays still occur.
3. Double Buffering
(Ping-Pong Buffers)		 OS assigns two buffers (Buffer A and Buffer B). While the CPU/application is reading data from Buffer A, the I/O device is simultaneously filling Buffer B! Once full, roles are reversed. Completely decouples producer and consumer; dramatically accelerates throughput!
4. Circular Buffering A queue of three or more buffers arranged in a circle. Used when bursts of heavy I/O occur, preventing bottlenecks when consumption momentarily slows down. Optimal performance for peak bursty I/O environments (e.g., high-speed network streaming).
